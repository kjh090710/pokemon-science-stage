# StageCue Studio 검증 기록

배포·브라우저 관찰 기준일: 2026년 10월 25일, 한국 시간. 소스 재검토·빌드 확인일: 2026년 10월 26일. 배포 상태, 실제 브라우저 관찰, 소스 검토를 구분해 기록합니다. 아래에 없는 기능은 검증 완료로 간주하지 않습니다.

## 2026년 10월 26일 재검토

- `src/App.tsx`의 “저장하지 않은 변경” 대화상자 포커스 수정분을 다시 소스 검토했습니다. 초기 “계속 편집” 포커스, 현재 활성화된 버튼 기준 Tab 순환, 대화상자 밖으로 벗어난 포커스 복귀, Escape 닫기, 이벤트 해제 및 이전 포커스 복원 경로에서 추가로 사용을 막는 문제는 발견하지 않았습니다.
- `npm.cmd run build`를 실행해 종료 코드 0을 확인했습니다. TypeScript 검사와 Vite 프로덕션 빌드가 완료되었습니다.
- 이 재검토에서 전체 키보드 흐름이나 모바일 브라우저를 새로 실행 검증하지는 않았습니다. 아래의 실제 브라우저 관찰 결과는 10월 25일 기록입니다.
- 사용자는 Google OAuth 클라이언트 생성 완료를 알렸으며, 기존 클라이언트와 연동 설정을 확인 중입니다. Google 로그인부터 Supabase 콜백까지의 실제 성공 흐름은 아직 검증 완료로 기록하지 않습니다.
- 아래 배포 표는 10월 25일의 `f330dd0` 스냅샷입니다. 대화상자 수정분은 현재 소스에 있으며, 이 문서의 재검토 시점에는 새 커밋·재배포 완료를 확인하지 않았습니다.

- 인증 화면이 공개 주소에서 정상 표시되었습니다.
- [로그인 없는 체험](https://stagecue-studio.vercel.app/demo)에서 포켓몬 템플릿의 **28개 장면과 6개 음원**을 불러왔습니다.
- 장면 추가 → 이름 변경 → 복제 → 위로 이동을 조작해 **30개 장면**이 되는 것을 확인했습니다.
- 위 실험 편집을 저장하지 않고 새로고침했을 때 원래 **28개 장면**으로 돌아왔습니다. 이 관찰은 저장하지 않은 변경의 복원이며, 클라우드 저장 검증이 아닙니다.
- 19번째 황금빛 호수를 선택한 뒤 이미지의 `complete === true`, `naturalWidth === 1672`를 확인했습니다.
- 해당 관찰 동안 브라우저 개발 로그의 오류·경고는 비어 있었습니다. 모든 경로나 모든 네트워크 상황에서 로그가 없다는 보장은 아닙니다.

## 디자인 대조

지정된 1536×1024 편집기 컨셉과 아래 다섯 가지 기준을 대조했습니다.

| 기준 | 구현과 관찰 |
| --- | --- |
| 흰색·파란색·네이비 헤더 | 흰 헤더, `#2563eb` 강조, 네이비 제목과 아이콘 유지 |
| 왼쪽 장면 목록 | 넓은 화면에서 220px 장면 목록, 실제 장면 썸네일·번호·선택 상태·목록 스크롤 제공 |
| 중앙 16:9 배경 | 황금빛 호수 등 실제 공연 배경을 큰 16:9 미리보기로 표시 |
| 오른쪽 설정 | 넓은 화면에서 270px 검사 패널, 장면·음향 탭 제공 |
| 배경 아래 메모·음악 | 운영 메모와 해당 장면의 음악 큐를 미리보기 아래 배치 |

실제 확인 화면은 **1280×720**으로 컨셉보다 작습니다. 글자와 입력 컨트롤을 축소해 모두 끼워 넣는 대신 장면 목록·작업 영역·설정 패널에 내부 스크롤을 사용합니다. 따라서 화면 아래 항목의 노출 범위가 1536×1024 컨셉과 다릅니다. 픽셀 단위 일치 검증은 하지 않았습니다.

로컬 관찰 이미지는 `docs/qa/editor.png`, `docs/qa/controller.png`, `docs/qa/production-editor.png`에 보관되어 있습니다. `docs/qa/`는 Git에서 제외되므로 이 파일들이 배포물이나 원격 저장소에 포함된다고 가정하면 안 됩니다.

모바일용 CSS 분기는 구현되어 있으나, **모바일 브라우저에서 실제 동작과 배치를 확인한 기록은 아직 없습니다.**

## React 훅·접근성 소스 검토

설치된 `vercel:react-best-practices` 스킬과 `client-event-listeners`, `rerender-functional-setstate`, `advanced-event-handler-refs` 규칙을 읽고 현재 React/Vite 클라이언트 흐름에 적용되는 부분을 검토했습니다. RSC/SSR 전용 규칙이나 스타일 라이브러리 변경은 이 검토 범위에 넣지 않았습니다.

- 컴포넌트의 조건부 반환 전에 훅이 선언되어 있는지 확인했습니다.
- 전역 키보드·포커스 이벤트와 타이머·채널·오디오 정리 경로를 확인했습니다. 키보드 진행은 입력창·선택창·버튼의 키 입력을 가로채지 않으며, 드래그 정렬에는 위·아래 이동 버튼도 제공합니다.
- 비동기 업로드·미리듣기·목록 조회의 이전 요청이 새 상태를 덮어쓰지 않도록 최신 문서 참조와 요청 토큰을 사용하는 흐름을 확인했습니다.
- 저장 중 재저장 요청의 Promise 대기, 편집 중 새 변경 보존, 공연 진입 전 미디어 URL 준비 상태, 체험 저장 전 문서 검증 및 실패 처리 경로를 확인했습니다.
- 인증 입력의 라벨·자동 완성, 비밀번호 표시 버튼 이름, 오류 알림, 상태 메시지를 확인했습니다.
- 편집기 삭제·작품 생성/삭제 대화상자의 초기 포커스·Tab 순환·Escape·포커스 복원 코드를 확인했습니다. 접근성 검토는 소스 기준이며 스크린리더 전체 흐름이나 WCAG 준수 인증을 의미하지 않습니다.

검토 중 루트의 “저장하지 않은 변경” 대화상자에 포커스 관리가 없는 문제를 발견했습니다. 로컬 소스에서 초기 “계속 편집” 포커스, 활성 버튼 사이 Tab 순환, 대화상자 밖에서의 포커스 복귀, Escape 닫기, 이벤트 해제와 이전 포커스 복원을 추가한 것을 다시 확인했습니다. 수정 후 빌드가 통과했습니다. 이 수정은 위 `f330dd0` 배포 스냅샷 이후의 변경이며, 새 배포 반영이나 전체 키보드 흐름의 실제 브라우저 검증까지 완료했다고 주장하지 않습니다.

## 아직 완료하지 않은 실서비스 검증

- Google OAuth 클라이언트는 10월 26일 사용자에게 생성 완료 보고를 받았습니다. 기존 클라이언트·Supabase 설정 확인과 Google 계정 로그인부터 콜백까지 이어지는 실제 성공 흐름 검증은 아직 완료하지 않았습니다. 10월 25일에는 설정 단계에서 사람의 확인/MFA가 필요했으며, 현재 인증 상태를 이 과거 기록만으로 판단하지 않습니다.
- Supabase에 로그인한 실제 사용자로 작품 생성·저장·복제·삭제, 이미지/음원 업로드, 서명된 미디어 URL의 재생을 끝까지 수행한 브라우저 검증은 아직 없습니다.
- 삭제 대기 작품의 잔여 파일 자동 정리와 서로 다른 사용자 간 접근 격리는 소스·정책 검토와 실제 서비스 브라우저 검증을 구분해야 합니다. 이 문서는 해당 기능의 실제 성공을 주장하지 않습니다.
- 비밀번호 재설정 메일 수신부터 새 비밀번호로 재로그인까지의 외부 메일 흐름도 아직 확인하지 않았습니다.
- 모바일 브라우저, 실제 빔 프로젝터, 네트워크 단절·URL 만료 환경은 별도 확인이 필요합니다.

기본 템플릿과 로그인 없는 편집·저장·무대 진행의 관찰 결과가 있으며, 인증과 사용자별 클라우드 미디어 흐름은 위 설정과 실계정 검증이 끝난 뒤 별도로 기록해야 합니다.
